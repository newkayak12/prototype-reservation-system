# V2 Open RFC 마감 계획 · 리스크 레지스터 · 제안 (round-2)

> ⚠️ **작업용 계획 문서 (비-git, 커밋 안 함).** 12개 Open round-2 RFC(003~014)를 "닫으려면" 무엇이 남았는지를 RFC당 1에이전트로 스캔해 종합한 산출물.
> 생성: 2026-06-18 · 대상: RFC-003~014 (002 인덱스 제외) · 라운드3(015~021)·이벤트 정체성 RFC([[RFC-021-event-identity-and-global-ordering]])는 별도 트랙.
> 판별 원칙: **숫자 보류(파티션/TTL/RPO/커버리지/lag)는 마감 차단 아님.** "정확성 규칙"(handler/projector/saga를 짜려면 발명해야 하는 한 줄)이 비면 진짜 미결.

---

## 0. 한 줄 판정

**지금 닫을 수 있는 RFC = 4개 완전(008·009·010·011) + 2개 핵심(003·004).** G0(이벤트 스토밍 재실시) 대기 잔여 5개(004 토픽목록 · 006 분류표값 · 007 ADR-08 · 012 가드표 · 013 엔드포인트). **모든 마감의 공통 선결 = 9개 Proposed ADR(04·06·07·09·10·11·12·13·14)의 `닫기=비준(ratify)` 실행** — 단 ADR 비준은 **user 권한**, 에이전트는 diff만 준비(자동 flip 금지).

## 3. 의존성 · 마감 웨이브 (순서)

```
W0 (즉시·병렬)      008  009  010  011
                      │
W1 (코어·병렬)        004 ──→ 003        (004 먼저 비준 권장: inbox·체크포인트·봉투 확정)
                      │         │
W2 (종속)          005+006   012(부분)  013(방향)
                   (한 쌍)      │
W3 (이행·사가)              014       007(규칙 착지, ADR-08만 G0후)
                      │
G0 백로그 (일괄)   004토픽 · 006분류표 · 007 ADR-08 · 012가드표 · 013엔드포인트
```

**의존 엣지:**
- **004 → 003** — projector 멱등 책임 배치가 RFC-004 inbox 결정에 종속(약한 엣지: '누적·증분 반드시 가드'는 이미 DD03). 병렬 가능하나 004 먼저.
- **004 → 012** — 체크포인트/오프셋 저장 위치 공동 소유. 012의 dedup 창·catch-up 재개가 여기 종속.
- **003 → 013** — 013 §2 202 결과확인이 003 read-your-writes를 '빌려 씀'. 003이 못 박지 않는 한 202 위치토큰 계약은 미정 → 013은 방향만 닫고 토큰은 위임.
- **005 ↔ 006** — 콜드 복호↔핫키 정합 상호 미룸 → 반드시 동반 비준.
- **012 → 014** — 014 백필이 012의 구독먼저·백필나중·멱등을 전적 재사용 → 014는 012 직후 동시 비준.
- **009 → 004(+DD02)** — DD10이 trace-meta를 'Kafka 헤더+DD07 봉투'에 싣는다는데 DD07에 봉투 섹션 부재 → 009 닫기 전 DD07 봉투 슬롯 1줄 또는 RFC-004 위임 명시(안 하면 DD10 dangling).
- **013 → ADR-16(이미 닫힘)** — DD12 어휘를 비관락에 동기화만(동시성 재개 금지).
- **005/014 → ADR-10** — 런타임 실패모드(005)·genesis-type(014)이 둘 다 ADR-10/DD08 §1.4 레지스트리에 착지 → ADR-10 승급 시 함께 반영.

**G0(이벤트 스토밍) 차단:** RFC-007 · RFC-012 (잔여 표/계약 값이 카탈로그 의존). 나머지(004·006·013)는 메커니즘 닫고 *값만* G0로 분리.

## 4. 제안 사안

1. **마감의 원자 단위 = `RFC 닫기 + 대상 ADR 비준 + §미결정 정리` 한 묶음** *(R1 해소)*
   12개 중 8개의 닫기 액션이 'ADR Proposed→Accepted'다. RFC만 닫고 ADR을 두면 권위문서/설계 모순이 영구화. 각 RFC를 닫을 때 (a) ADR 상태 승급 (b) §미결정/TBD에서 DD 확정항목 이전·잔여 재라벨 (c) 상호참조 보강을 **한 PR로**. **비준은 user 권한 → 에이전트는 diff만, 자동 flip 금지.**

2. **G0(이벤트 스토밍 재실시)를 다음 선결 작업으로 — 5개 RFC의 잔여가 인질**
   007(3-event payload·correlation·분류표→ADR-08), 012(가드 귀속표), 006(분류표 값), 004(토픽 목록), 013(엔드포인트)이 카탈로그에 묶임. 단 이들의 **메커니즘/규칙은 G0 없이 닫히므로**, G0 대기 항목만 각 RFC에서 떼어 'G0 백로그'로 모으고 본체는 부분/방향 마감. G0 종료 시 백로그 일괄 비준.

3. **RFC-005+006은 반드시 한 쌍으로, 콜드복호↔핫키 정합 동반 비준** *(R10)*
   교착(서로 미룸) 해소: 'S3 export 후 파티션 drop하되 키는 핫 저장소 영속(콜드 이관 금지), 콜드 재생은 핫 키 참조' 1규약을 양 DD(08/15)에 동시 착지·비준하고 같은 사이클에서 닫음.

4. **체크포인트 위치·스왑창 invariant는 지금 결정 가능 → RFC-004와 묶어 RFC-012 부분 비준** *(R6·R7)*
   012 잔여 3개 중 2개(체크포인트 위치·스왑창 invariant)는 G0 불요. RFC-004 마감 시 DD07에 체크포인트 위치 못박고(권장: query DB checkpoint 행·원자 커밋), DD03에 스왑창 invariant 1줄 → 가드 귀속표만 G0로 남기고 신규 '프로젝션 운영 전략' ADR로 부분 비준.

5. **RFC-007 정확성 규칙을 지금 DD06에 착지해 'G0 잔여만' 상태로 좁혀라** *(R8)*
   PM confirm/timeout/보상 handler에 필요한 규칙(두 시계 충돌·만료 hold confirm 거부+보상, paid-after-expiry 보상, PM rehydrate+open-saga deadline read model, 다단계 보상 순서/원자성, consume-then-emit 멱등, 부분 보상 추적)은 G0 독립 → 지금 DD06 착지. ADR-08 비준만 G0 뒤로.

6. **교차문서 빈자리 2건을 닫기 전에 메워라** *(R9 + dangling)*
   (1) RFC-009 전: DD07에 메시지 봉투/헤더 슬롯(correlationId·causationId·traceparent·event_id) 1줄, 또는 RFC-004 위임 명시. (2) RFC-013 전: DD12 §3 낙관락 어휘를 ADR-16 비관락으로 동기화(어휘만). 둘 다 정확성 규칙이 아니라 정합 빈자리 → 1줄 보강.

7. **마감 순서:** W0 즉시(008·009·010·011) → W1 코어(004→003) → W2 종속(005+006·012부분·013방향) → W3 이행/사가(014·007) → **G0 백로그 일괄 청산**.

## 5. RFC별 카드 (부록)

> 각 RFC의 `닫는 행위 권고` + `지금 결정 못 하는 openDecision`. 닫을 때 이 카드대로.

### ✅ W0 — 즉시 단독 마감

- **RFC-008 배포·인프라·운영** — DD09가 방향 전부 흡수(보강 완료). ADR-12·13 상태 Proposed→Accepted 비준하고 닫음. 잔여는 숫자/목록(측정·구현)·위임(호스팅·GitOps)이라 비차단.
- **RFC-009 관측성** — DD10 6개 결정 자족. RFC-009 닫고 DD10 비준. **단 닫기 전 DD07에 trace-meta 헤더 슬롯 1줄 보강(또는 RFC-004 위임 명시)** — cross-doc 메움.
- **RFC-010 테스트·품질게이트** — 정책/정확성 전부 DD11 착지(§5.5~5.8). ADR-14 비준. 남은 건 숫자·측정 트리거뿐.
- **RFC-011 모듈구조·이행** — 5개 규칙(도메인 거처·매핑 수동·순서 의존성1차·단위=컨텍스트1개=사이클1개·신규기능 별도 command 컨텍스트) DD01·DD04·ADR07 착지. **닫기 직전 ADR-07 line59 'core-module 분리 미결' 잔재를 DD01 확정(비채택) 가리키도록 정리** 후 ADR-06·07 비준.

### ✅ W1 — 읽기·메시징 코어

- **RFC-004 메시징·전달보장** — 메커니즘 9건(수동 커밋·event_id dedup·SKIP LOCKED·cooperative-sticky·병렬상한=파티션수·store-replay 재구축…) 전부 DD07 착지. inbox dedup 키 긴장은 RFC-021/ADR-22로 해소. **토픽 목록만 G0로 분리**, ADR-09 비준. (파티션 초기값·lag·DLQ 곡선은 숫자 보류)
- **RFC-003 읽기모델 일관성** — 정확성 전부 DD03 착지. **닫기 전 ADR-04를 RFC-003 비준으로 1회 개정**(상위에 RFC-003 추가, §미결정의 '지연 허용치·예외 화면·lookup 귀속'을 '정책 결정됨·숫자/표만 측정 보류'로 갱신). RFC-004/012/G0 종속은 숫자·구현이라 비차단.

### ⚠️ W2 — 스토어·PII·재구축·API

- **RFC-005 이벤트스토어·스키마진화** *(partial)* — ⛔ openDecision: **업캐스트/역직렬화 런타임 실패 모드(read-path)** — malformed이거나 (eventType,fromVersion) 업캐스터 부재 시 reject/halt/skip/poison 중? (ADR-10은 시작 시 키충돌 fail-fast만 정함, 런타임 무규정). 이 1줄이 비면 loadAsOf/리플레이/재구축 코드를 못 짬. → ADR-10·DD08 §1.4에 결정 + 직렬화 규약 ADR-05 착지 + ADR-10 승급 + RFC-006 동반.
- **RFC-006 PII·보안** *(partial)* — 정확성 전부 DD15 착지. ADR-11 비준(user 승인). **PII 분류표는 G0 후 별도 ADR의 *값*일 뿐, 규칙은 이미 결정** → 닫기 비차단.
- **RFC-012 프로젝션 재구축·catch-up** *(partial)* — ⛔ openDecisions: (1) **체크포인트 저장 위치**(`__consumer_offsets` vs query DB 행) (2) **프로젝터별 가드 귀속표**(G0 의존) (3) **스왑창 이벤트 invariant**. (1)(3)은 RFC-004와 묶어 지금, (2)는 G0 직후. 신규 '프로젝션 운영 전략' ADR로 비준.
- **RFC-013 API 계약** *(partial)* — ⛔ openDecisions: (1) **락충돌(lock-wait/DuplicateKey) 즉시 409 vs 202 결과조회 통지** (2) **동기 4xx 거절 vs 202 경계**. 둘 다 RFC-003 read-your-writes 결론에 종속 → 방향(task-based·202·서버멱등·3분류 에러·단일표면·cursor)만 신규 ADR로 비준, DD12 §3 어휘를 ADR-16에 동기화, 두 규칙은 위임 표기.

### ⚠️ W3 — 이행·사가

- **RFC-014 데이터 이행(genesis)** *(partial)* — ⛔ openDecision: **genesis = 별도 eventType(RestaurantImported) vs Created+source=imported 플래그**. → 별도 eventType 권장을 ADR-10/DD08 §1.4 + DD04 §시딩에 착지. 백필 재사용 비준은 RFC-012 직후 동시.
- **RFC-007 사가·프로세스매니저** *(partial)* — ⛔ openDecisions(G0 독립, 지금 DD06 착지): confirm 시 hold 재검증·paid-after-expiry 보상 / PM 크래시 rehydrate+open-saga deadline read model·부분 보상 추적 / 다단계 보상 순서·원자성·consume-then-emit 멱등. **G0 종속(보류):** 3-event payload·correlation key, 취소/노쇼/환불 분류표 → ADR-08 비준은 G0 후.

## 6. 다시 열 때

- 위 **현황표(§1)** = 진행 보드. ✅는 오늘 비준 가능, ⚠️는 카드(§5)의 openDecision 먼저.

- ADR 비준 diff는 에이전트가 준비 가능, **flip은 user**.

진짜 발견 — 어느 한 문서도 안 가진 횡단 결정 7개

(괄호는 독립적으로 같은 걸 지적한 클러스터 수 — 신호 강도)

① 글로벌 순서 & 이벤트 정체성 — 모순 확정 (4개 클러스터)
adr/05 event_store에 event_id 컬럼이 없는데, adr/09 멱등 컨슈머/inbox는 메시지 정체성을 요구하고 causationId의 출처도 불명. 게다가 sequence_no는 per-aggregate라 글로벌
단조 커서가 없어 프로젝션 재구축 스캔 순서를 정의할 수 없다. → 쓰기·읽기·사가가 전부 "per-aggregate 순서만 보장" 위에 서 있는데, 프로젝션·사가는 애그리거트를
가로지른다. adr/05가 event_id + 글로벌 정렬 컬럼을 추가해야 함.

② read-your-writes + 202 결과 조회 — 가장 많이 참조된 미결 (4개 클러스터)
202 비동기 계약 전체가 여기 매달려 있는데 RFC-003은 "화면이 필요하다고 증명되면"으로 미룸. 그 결과:
- 클라가 cancel 성공을 알 방법이 없음 (poll/SSE/ws 미정)
- 422 도메인 거부와 409 락 충돌이 동기 응답인지 결과조회 시점인지 미정 → 에러 계약이 두 모양
- ownership 변경 시 stale 권한 창 (인가도 여기 종속)
  → 신규 화면이 이미 V1에 있으면 "나중에 증명" 불가. ADR 1개로 잠가야 함.

③ PII가 파이프라인 전 구간에서 누락 (3개 클러스터)
크립토 셰딩(adr/11)은 정상 상태만 설계됨. 누락된 구간:
- genesis import — V1 행 스냅샷을 통째 담은 genesis 이벤트가 append-only 스토어에 PII를 박아넣음 (rfc014엔 PII 단어 자체가 없음)
- Kafka 토픽 — 발행 페이로드가 _encrypted 봉투인지 평문인지 미명시 (retention vs 삭제 충돌 미직면)
- 프로젝션/Redis — 복호화된 PII가 read model에 적재되는지, 삭제 시 재구체화/eviction 하는지 미정
  → 키 지워도 이름이 query MySQL·토픽에 남으면 셰딩이 무의미.

④ key-store DR 복구 역설 — 모순 (PII)
"DR 위해 키 백업" vs "셰딩 위해 키 백업에서 삭제/제외"가 정면 충돌. key_store 디스크 분실 = 전 고객 PII 영구 복구불가인데, 복구 경로를 RFC-018↔RFC-006이 서로에게 미룸.
어느 쪽이 이기는지 아무도 안 정함.

⑤ Flyway / 마이그레이션 실행 주체 (3개 클러스터)
command DB + query DB 물리 분리 + 도메인별 스키마인데 — 누가 DDL 소유? 배포 시 어느 워크로드가 Flyway 실행? projector 롤아웃과 순서는? CLAUDE.md상 Flyway는
adapter-module 단일 DS. 어느 문서도 안 가짐.

⑥ strangler 혼재 창의 컨텍스트 간 ACL (migration)
"Zero-Payload라 안전"이라고만 함. 2~4단계에서 reservation(V2)이 menu/company(V1)와 대화하려면 old↔new 스키마를 잇는 anti-corruption 매핑이 필요한데 — strangler의 진짜
어려운 부분이 hand-wave. + adr/13("모든 query 타깃은 projection"이어야)와 "5단계는 V1 유지"가 모순.

⑦ 사가 크래시 복구 + stuck 사가 관측 + poison 런북 (2개 클러스터)
PM은 "ES 스트림"인데 재시작 시 어떻게 rehydrate/resume 하는지, 열린 사가를 deadline으로 조회할 read model이 없음(스트림은 쿼리 불가), 부분 보상까지 추적 못 함(RFC-007
스스로 인정), poison 메시지 재주입 런북 부재. + paid-after-expiry 레이스 (결제 확정이 좌석 해제 후 도착 → 돈만 받고 좌석 없음, 보상 경로 미연결).
