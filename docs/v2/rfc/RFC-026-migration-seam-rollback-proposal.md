# RFC-026 — V1→V2 마이그레이션 접합·롤백·성공기준 (안 제시 · 미채택 · 구현 비참조)

> ⚠️ **이 RFC는 안(案)만 담는다.** C16(V1→V2 데이터 이행)은 이 프로토타입에서 **실제 수행하지 않는다** — 이행할 실제 V1 운영 데이터·트래픽이 없다. 아래는 "실제로 옮긴다면 이렇게 하는 게 좋다"는 **설계 제안**일 뿐이며, **실제 구현은 이 문서를 참조하지 않는다.** 따라서 결정(🏷 합의)·DESIGN 문서·ADR 비준으로 이어지지 않는다. C16 트리아지 항목을 "안은 있으나 미채택"으로 닫기 위한 기록이다.

- **상태**: 📎 안 제시 · 미채택 (구현 비참조) — 2026-07-04
- **사이클**: `20260612-v2-cqrs-es-architecture`
- **선행**: [[RFC-013-data-migration-genesis-events]](이행 원안·클린 슬레이트) · [[RFC-021-event-identity-and-global-ordering]](`event_id`) · [[RFC-025-ordering-relay-dlq-reconciliation]](LWW·재구축) · [[RFC-011-projection-rebuild-catchup]](재구축) · 인덱스 [[RFC-INDEX]]
- **분석 출처**: [[06-design-weakness-triage]] C16 (D-005 Weakness §4.3·§4.6·§4.7, 라인 173·174·176·179) · **C45** (전환 순서 규칙 정합 — 안 ③′로 흡수)
- **왜 결정으로 안 가나**: 실제 이행 대상이 없어 검증할 수 없다. 안을 확정하면 검증 안 된 인프라 가정을 기정사실로 박게 된다 → 미채택으로 남긴다.

---

## 배경 (Background)

### 시나리오: 예약 데이터를 V1에서 V2로 옮기는 전환 기간

**V1만 있을 때는** 예약이 한 DB에 쓰이고 읽힌다. 옮길 이음매가 없다.

**V1→V2 전환 기간에는** 두 시스템이 함께 돈다. 기존 데이터를 V2에 통째로 심고(genesis 시딩), 그 뒤 V1의 변경을 V2로 계속 흘려보내며(단방향 동기), 어느 순간 트래픽을 V2로 넘긴다(컷오버). 이 세 동작의 이음매를 안 정하면 같은 예약이 두 번 들어가거나(이중반영) 빠지고(유실), 문제가 생겨 V1로 되돌리면(롤백) 그 사이 V2에만 쌓인 예약이 증발한다.

### 먼저 용어

| 말 | 뜻 |
|---|---|
| **genesis 시딩** | V1의 현재 상태를 V2의 최초 이벤트로 통째로 심는 초기 적재 |
| **단방향 동기** | 전환 기간에 V1의 변경을 V2로만 계속 흘려보내는 파이프(V2→V1은 없음) |
| **병행 창** | V1·V2를 함께 돌리는 전환 기간 |
| **스냅샷 커서** | genesis 시딩이 "어느 시점의 V1 상태까지 떴는가"를 가리키는 지점 |
| **동기 오프셋** | 단방향 동기가 "어느 변경부터 흘려보내기 시작하는가"를 가리키는 지점 |
| **접합점** | 커서와 오프셋이 맞물리는 이음매 — 겹치지도 비지도 않아야 이상적 |
| **LSN/binlog 위치** | DB가 커밋을 매기는 단조 증가 좌표. "어느 트랜잭션까지"를 하나의 숫자로 가리킴 |
| **CDC** | DB 트랜잭션 로그(binlog)를 커밋 순서로 tailing (Debezium 등) |
| **컷오버** | 트래픽을 V1에서 V2로 넘기는 전환 순간 |
| **롤백 / fix-forward** | 문제 시 V1로 되돌리기 / 되돌리지 않고 V2에서 고쳐 전진 |

---

## 맥락 (Context)

D-005가 세 축을 스스로 미해결로 적어뒀고(§4.3 접합점 "경계가 없다", §4.7 롤백 유실, §4.6 성공 게이트 "약하다"), RFC-013은 이 셋을 "Design에서 검증"으로 이월하고 클린 슬레이트라며 하류 산출물 없이 종결했다. 대응 ADR도 없다.

- **자산 — `event_id` 정체성이 있다.** [[RFC-021-event-identity-and-global-ordering]]. → genesis·동기 이벤트에 결정적 `event_id`를 부여하면 중복을 dedup으로 흡수할 수 있다.
- **자산 — LWW·재구축이 있다.** [[RFC-025-ordering-relay-dlq-reconciliation]]·[[RFC-011-projection-rebuild-catchup]]. → 접합·복구 안이 새 machinery 없이 기존 자산 위에 선다.
- **한계 — 검증 불가.** 실제 이행 대상이 없다. → 확정하면 검증 안 된 가정을 박게 된다. 그래서 안까지만.

핵심 긴장 — **세 축(접합·롤백·성공기준)의 "좋은 안"을 기존 V2 자산 위에서 제시하되, 검증 못 하므로 결정으로 승격하지 않는다.**

## 제안 (안만 — 미채택)

### 안 ① 접합점: 일관 스냅샷 LSN을 이음매로, dedup을 안전망으로

**문제.** genesis가 "3시 정각 V1 상태"를 떴는데 3시~컷오버 사이 V1 변경이 (a)genesis·(b)동기 양쪽에 잡히면 이중반영, 어느 쪽에도 안 잡히면 유실.

**안.**
1. **일관 스냅샷 + 같은 LSN에서 동기 시작.** genesis 스냅샷을 트랜잭션 일관 지점(binlog 위치 `P`)에서 뜨고, 단방향 동기(CDC)를 **정확히 `P`부터** 시작한다. `≤P`는 genesis, `>P`는 동기 — 겹침도 빈틈도 원리상 없다. (Debezium `initial` 스냅샷 → 같은 오프셋에서 stream 이어받기의 표준형.)
2. **결정적 `event_id` + inbox dedup을 안전망으로.** genesis·동기 이벤트의 `event_id`를 `V1 PK + 버전`에서 결정적으로 파생하고, V2 inbox가 dedup([[RFC-021-event-identity-and-global-ordering]]·[[RFC-025-ordering-relay-dlq-reconciliation]] LWW). → 접합이 흐려도 **겹침은 무해**해진다.

**설계 원칙**: *빈틈 없이 맞추려 애쓰기*보다 **겹치게 만들고 dedup으로 흡수**. 유실(빈틈)이 유일한 진짜 적이므로, 이음매를 의도적으로 overlap 쪽으로 편향시킨다.

### 안 ② 롤백: fix-forward를 기본, 짧은 역동기 창은 옵션

**문제.** 단방향(V1→V2)이라 컷오버 후 V2 신규 예약은 V1에 없다. 이 상태로 V1 롤백하면 그 예약이 증발.

**안 (권장순).**
1. **fix-forward 기본 + 롤백 포기 시점을 컷오버로 명시.** 컷오버 후 V2가 진실원. 문제는 되돌리지 않고 V2에서 고쳐 전진한다. 근거: V2는 이벤트 소싱이라 재구축 가능([[RFC-011-projection-rebuild-catchup]])하고, "컷오버 후 V2가 truth"는 ADR-06 방향과도 정합.
2. **(옵션) 바운드 역동기 창.** 하드 롤백 보장이 꼭 필요하면, 컷오버 직후 **짧은 신뢰 창** 동안만 V2→V1 임시 ACL(anti-corruption layer)로 V2 이벤트를 V1에 되반영. 양방향은 비싸므로 창을 짧게 못박는다.
3. **(기각) 병행 창 dual-write.** V1·V2 동시 쓰기는 두-마스터 정합 문제를 되불러온다 — V2가 벗어나려던 바로 그 문제. 학습용 프로토타입엔 과함.

### 안 ③′ 전환 순서: leaf-first는 tie-break, fail-fast가 1순위 (C45)

**문제.** §4.1이 "leaf-first(잎 먼저)"를 1순위 규칙으로 못 박았는데, 실제 순서표(§4.2: 1 timetable → 2 reservation → 3 restaurant → …)는 허브인 reservation을 그것이 의존하는 restaurant보다 **앞**에 둔다. 규칙 ↔ 순서 모순. 파생 피해: reservation을 먼저 옮기면 restaurant가 아직 V1이라 이벤트를 안 뿜어 **reservation 프로젝션의 식당명 비정규화**([[DESIGN-004]] §4.5)가 성립 못 한다.

**안.**
1. **규칙 우선순위 정정** — 실제 순서표는 *fail-fast*(위험·핵심 ES인 reservation을 앞세워 문제를 빨리 드러냄)로 만들어졌다. 그러니 **fail-fast가 1순위, leaf-first는 tie-break**라고 문서를 바로잡으면 모순이 소멸한다(순서표는 안 바뀌고 규칙 *서술*만 정정). 결과에 맞춰 규칙을 사후에 뒤집은 게 아니라, 애초에 fail-fast가 우선이었음을 명시하는 것.
2. **식당명 비정규화 브리지** — reservation을 restaurant보다 먼저 옮기는 창 동안: (a) 임시 이벤트 브리지로 V1 restaurant 변경을 V2로 흘려 비정규화를 채우거나, (b) 비정규화 필드를 restaurant 전환 후 **backfill**(프로젝션 재구축, [[RFC-011-projection-rebuild-catchup]]). 어느 쪽이든 "허브를 먼저 옮기는 대가"를 명시적으로 갚는다.

> C45(순서 규칙 정합)는 C16과 같은 D-005·같은 미이행 전제라 이 RFC에 흡수한다. 실제 이행이 없으므로 이 안도 미채택 — 실 이행 사이클에서 검증.

### 안 ③ 실효 성공기준: 복사본이 아니라 파이프라인을 검증

**문제.** "재구성 상태 = V1 현재 상태"는 genesis가 V1을 복사한 것이라 정의상 참 → 순환. 아무것도 검증 못 함.

**안 — 셋을 함께.**
1. **shadow-read 패리티.** 컷오버 전후 라이브 트래픽으로 같은 질의를 V1·V2 읽기 모델에 동시에 던져 N시간 허용오차 내 일치 확인. (복사본↔원본이 아니라, **동기 파이프를 거쳐 독립 진화한** 두 상태를 비교 → 파이프가 검증된다.)
2. **불변식·정합 체크.** 슬롯 이중예약 0, 활성 예약 수 정합 등 업무 불변식이 V2에서 독립적으로 성립.
3. **동기 완결 SLI.** 동기 오프셋이 head까지 따라잡음 · DLQ 0건 · V1 변경 건수 == V2 적용 건수(`event_id` 정합).

성공 = **shadow-read 패리티 + 불변식 + 동기 완결 정합.** 명시적으로 "genesis == V1"은 성공기준에서 뺀다.

## 이 안을 채택하지 않는 이유 (명시)

- **검증 대상 부재.** 옮길 실제 V1 데이터·트래픽이 없어 세 안 중 무엇도 실증할 수 없다.
- **미검증 가정 동결 위험.** 확정하면 CDC 커넥터·역동기 ACL·shadow 인프라 등 검증 안 된 인프라를 기정사실로 박는다([[no-smuggling-undecided-infra]] 취지).
- **결론.** 안으로 남기고 **미채택**. 실제 이행이 필요해지는 날 이 문서를 *출발점*으로 삼아 새 사이클에서 검증 후 확정한다. 그 전까지 **실제 구현은 이 문서를 참조하지 않는다.**
