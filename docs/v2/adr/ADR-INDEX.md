# ADR-INDEX: V2 ADR 작성 계획

design_doc가 확정한 결정들을 ADR로 옮기는 작업 계획이다. 무엇을, 어떤 근거로, 어떤 순서로 쓸지 정한다.

- **사이클**: `20260612-v2-cqrs-es-architecture`
- **근거**: `docs/v2/design_doc/` (DESIGN-001 ~ 020) · [[DESIGN_DOC-INDEX]]
- **형식**: MADR 4.0 ([[ADR-TEMPLATE]])

---

## 작성 규칙

- **번호**: 기존 ADR 스케치의 토픽 번호를 그대로 ADR 번호로 계승한다. ADR-001·002가 이미 이 규칙으로 작성됐다. 스케치가 없던 신규 결정은 빈 번호(21)와 22 이후에 배정한다.
- **상태**: 모든 ADR은 `Proposed`로 작성한다. `Accepted` 전환은 사용자 권한이다.
- **작업 단위**: 솔로 개발 · 의존성 순서대로 한 번에 하나씩 전사한다. 대부분 상위 RFC가 이미 합의 상태라, "새 결정"이 아니라 "확정된 결정의 전사"다.

**상태 범례**

| 표기 | 뜻 |
|------|-----|
| ✅ | 작성 완료 (Proposed) |
| ⏳ | 작성 대기 — 근거 문서 확정, 전사만 하면 됨 |
| ✏️ | 재작성 필요 — 스케치 내용이 최신 결정과 어긋남 |
| ◽ | 조건부 — 필요성이 입증되면 작성 |

## 손봐야 할 항목

- **ADR-025** — DESIGN-004가 "필요 시"로 남긴 조건부 결정이다. 읽기 신선도 예외가 실제로 필요해질 때만 작성한다.
- **ADR-027** — 스케치에 없던 신규 결정. DESIGN-003 자기리뷰가 채택했으나 명명 불변식으로 못박히지 않아 트리아지 C-1로 남아 있던 event_store·outbox 원자성 전제를 확정하고 CDC 졸업 경로를 지정한다(2026-07-28).

## 근거 매핑 요약

한 design_doc이 여러 ADR을 낳고, 한 ADR이 여러 design_doc에서 근거를 끌어온다. 상세는 [[DESIGN_DOC-INDEX]] 참조.

- **DESIGN-009**(최대 합류점) → ADR-005 · 010 · 018 · 022
- **DESIGN-010** → ADR-012 · 013 · 024 · 026
- **DESIGN-002** → ADR-001 · 003 · 007
- **DESIGN-008** → ADR-009 · 021
- 나머지는 대체로 1 design_doc : 1 ADR
