# ADR: 애그리거트 동시성 — 비관 락(Redisson + DB 폴백) + `(aggregate_id, sequence_no)` UNIQUE 백스톱

> **개정 이력**: 2026-06-16 최초 Proposed는 *낙관적 동시성*(UNIQUE=expected-version, 비관 락 기각)이었다. 2026-06-17 [[RFC-014-aggregate-concurrency-control]] §재개로 **비관 락**으로 전환하며 본 ADR을 재작성한다. 파일명(`16.optimistic-...`)은 안정 링크 유지를 위해 보존한다 — 내용이 정본.

- **상태**: Proposed (2026-06-17, 비관 락 개정) · 사이클 `20260612-v2-cqrs-es-architecture`
- **상위**: [[RFC-014-aggregate-concurrency-control]] · **설계**: [[05-aggregate-design]] · [[02-write-model]]
- **연관**: [[05.event-store-mysql-table]] (UNIQUE 백스톱 출처) · [[09.event-ordering-and-delivery-guarantee]] (파티션 키=aggregate_id) · [[08.saga-orchestration-vs-choreography]] (교차는 사가) · [[19.caching-redis-role]] (Redisson 락 = 도메인 동시성)

## 맥락

V1에서 예약 한 건은 사실상 DB 트랜잭션 하나였다 — 행 잠금과 유니크 제약이 경합을 막아 줬다. V2의 ES 컨텍스트에는 그 잠글 행이 없다([[RFC-001-v2-cqrs-and-event-sourcing]]). 현재 상태는 이벤트 리플레이로 재구성하고([[02-write-model]]), 쓰기는 스트림 끝에 *append*할 뿐이다. 두 손님이 같은 7시 테이블을 버전 N에서 로드해 둘 다 "자리 있음"으로 판단하면, 제어가 없는 한 둘 다 `SeatHeld`를 append해 한 자리가 두 번 점유된다.

[[05.event-store-mysql-table]]가 `(aggregate_id, sequence_no)` UNIQUE를 박아 뒀고, 이는 **스트림당 단일 라이터**를 구조적으로 보장한다 — 같은 버전 위에 두 append가 성공할 수 없다. 본 ADR은 그 위에서 **경합을 어떻게 다루는가**를 정한다: 충돌한 뒤 거절(낙관)하느냐, 미리 직렬화(비관)하느냐, 그리고 그 어느 쪽도 UNIQUE라는 최종 불변식을 대체하지 않는다는 점.

> 원안은 낙관을 택했으나, 핫 스트림(인기 슬롯=핫 스트림) retry storm/라이브락을 트레이드오프로 자인했다. [[19.caching-redis-role]]가 Redisson을 이미 provision했고, 예약 경합을 *질서 있는 큐*로 바꾸고 둘째 이후를 *확정적으로* 거절하는 편이 낫다고 판단해 비관으로 전환한다. 전체 재검토는 [[RFC-014-aggregate-concurrency-control]] §재개.

## 고려된 옵션들

### 경합을 무엇으로 막나
- **C-1 비관 락 — 분산 락(Redisson) + DB 폴백 (선택)**: 스트림을 잠가 라이터를 줄 세운다. 핫 스트림의 동시 리플레이→충돌→재시도 낭비를 큐로 바꾸고, 경합한 둘째를 재시도 없이 거절. 평소(무경합)에도 락 획득 비용을 내지만, 트래픽이 없는 학습 환경에서 그 비용은 명목상이며 분산 락 운영 학습가치가 상회.
- **C-2 낙관 + `(aggregate_id, sequence_no)` UNIQUE = expected-version (원안, 기각)**: 잠그지 않고 충돌 시 UNIQUE 위반으로 거절→재시도. 평소 비용 0이나 핫 스트림에서 retry storm/라이브락. **UNIQUE 자체는 본 결정에서도 백스톱으로 잔존**(낙관을 버리는 것이지 UNIQUE를 버리는 게 아니다).
- **C-3 낙관 + 별도 버전 컬럼**: 이미 가진 UNIQUE로 충분 — 기각.

### 락 제공자가 죽으면 (Redis 가용성)
- **A-1 낙관으로 폴백**: Redis 불가 시 낙관 재시도. 단순하나 *모드 전환*으로 의미론이 갈림.
- **A-2 DB 비관 락으로 폴백 (선택)**: Redis 불가 시 command DB lock-row `FOR UPDATE`. 비관 의미론 유지, command DB는 어차피 필수라 새 하드 의존 0.
- **A-3 락 필수(폴백 없음)**: Redis 다운=쓰기 중단. 가용성 회귀 — 기각.

### 락은 정확성을 보장하나
- **세 가지 사실**: 분산 락은 liveness지 safety가 아니다. [[19.caching-redis-role]]의 Redis는 단일 인스턴스·손실 허용·`allkeys-lru`라 락 키 evict·페일오버·리스 만료로 풀릴 수 있다. → **UNIQUE를 정확성 불변식으로 유지**(L0).

## 결정사항

**비관 락을 UNIQUE 앞단에 둔다. 정확성은 `(aggregate_id, sequence_no)` UNIQUE가, 경합 완화는 분산 락이 맡는다 — 락이 정확성을 대체하지 않는다.**

3층으로 분리한다.

- **L0 — 안전 불변식(항상)**: `(aggregate_id, sequence_no)` UNIQUE. append-only 스토어의 진짜 단일-라이터 보장. 어떤 락을 얹어도 **제거하지 않는다**. 락 유실 edge에서 이중 append를 최종 거절하는 백스톱.
- **L1 — 경합 직렬화(1차)**: 단일 `aggregate_id`에 대한 **Redisson 분산 락**. `lock(aggregate_id) → load(replay)=N → handle → append(N+1) → release`. Redis 정상 시 라이터를 큐로 세워 retry storm을 없앤다.
- **L1′ — 경합 직렬화(폴백)**: Redis 불가 시 **DB 비관 락**(per-aggregate lock-row `SELECT … FOR UPDATE`, 트랜잭션 스코프). **낙관으로 회귀하지 않는다** — 락 제공자만 Redis→DB로 강등.

부속 규칙:

- **락 범위 = 단일 `aggregate_id`만. 전역 락 금지.** 여러 애그리거트에 걸친 불변식은 전역 락이 아니라 **사가**([[RFC-006-saga-process-manager]])로 흡수한다(작게 유지 원칙·[[09.event-ordering-and-delivery-guarantee]] "교차는 사가"와 정합). 즉시 일관성(한 애그리거트)=비관 락, 최종 일관성(여러 애그리거트)=사가. 둘의 경계가 곧 애그리거트 경계다.
- **ES 쓰기 경로 한정.** 비-ES(상태+Outbox)는 DB 행 락 그대로(V1 유지). 서사: V1의 행 락을 ES가 없앤 자리를 분산/DB 락이 메우고, UNIQUE가 최종 심판.
- **dual-provider split-brain은 L0가 흡수**: 폴백 전환 창에 일부 노드 Redisson·일부 DB 락이 공존해도, 둘째 append가 UNIQUE로 거절돼 정확성은 유지된다(일시 비효율일 뿐 부정확 아님).
- **충돌 처리**: 락 보유로 동시 충돌은 대부분 소거. 잔여 표면 — ① lock-wait 타임아웃→재시도 신호(409/503), ② 도메인 거절(reload 시 판단 뒤집힘)→422/409 *확정적*, ③ 잔여 UNIQUE 위반(락 유실)→충돌 흡수(바운디드 재시도/409). [[12-api-contract]] 202 모델 안 노출 시점은 [[RFC-012-command-query-api-contract]]와 Design.
- **granularity 위임**: 락 단위=애그리거트=직렬화 단위. 핫스팟 경계(슬롯·좌석)는 경합 범위를 줄이는 방향으로 잘게 식별 — 경계 결정은 [[05-aggregate-design]]·이벤트 스토밍(🌱).
- **세 층 분리(불변)**: 동시성 충돌(쓰기 경합·command DB) ≠ 요청 멱등(중복 제출·HTTP·[[12-api-contract]]) ≠ 전달 멱등(중복 전달·메시징·[[07-messaging-topology]]).

> 결정의 한 줄: "잠그되 믿지 않는다 — Redisson(또는 Redis 다운 시 DB)으로 한 줄로 세우고, `(aggregate_id, sequence_no)` UNIQUE가 최종 심판. 전역 락은 없고, 교차는 사가."

## 장점
1. **핫 스트림이 큐가 된다** — 동시 리플레이→충돌→재시도 낭비가 직렬 진행으로, 둘째 이후는 재시도 없이 확정 거절(관측·UX 명료).
2. **정확성은 락과 무관** — L0 UNIQUE가 락 유실·split-brain·폴백 전환 모두에서 이중 점유를 구조적으로 막는다.
3. **가용성 유지** — Redis 다운에도 DB 비관 락으로 비관 의미론 보존, 새 하드 의존 0.
4. **인프라 추가 0** — Redisson은 [[19.caching-redis-role]]가 이미 provision.
5. **경계 일관** — 순서(파티션 키)·동시성(락 범위)·교차 일관성(사가)이 모두 애그리거트 경계에서 풀린다.

## 트레이드오프

### 선택한 방식의 한계
- 무경합 쓰기에도 락 획득 비용(평소 0이던 낙관 대비) — 학습 환경에선 수용, 실트래픽 시 재검토 트리거.
- 락 제공자 이원화(Redisson/DB)로 전환 창·split-brain 처리 복잡도 — L0가 정확성은 보장하나 운영 코드·테스트 부담.
- Redisson 리스 TTL·watchdog 튜닝, lock-wait 타임아웃 정책 등 분산 락 운영 표면 추가.

### 포기한 대안들
- **C-2 낙관(원안)**: 핫 스트림 retry storm/라이브락 — 비관으로 대체(UNIQUE는 백스톱으로 잔존).
- **A-1 낙관 폴백**: 모드 전환으로 의미론 분기 — DB 비관 폴백 채택.
- **A-3 락 필수**: Redis 다운=쓰기 중단, 가용성 회귀 — 기각.
- **전역 락**: 처리량 사망·작게 유지 원칙 위배 — 기각(교차는 사가).

## 미결정 사항 및 추가 논의 (→ 구현 사이클)
- Redisson 락 키 포맷·리스 TTL·watchdog 자동 연장, lock-wait 타임아웃·백오프.
- DB 폴백 lock-row 스키마·트랜잭션 스코프 해제, Redis up/down 판정(서킷 브레이커)·전환 창.
- 스냅샷이 낀 로드의 expected `sequence_no`(스냅샷 버전 + 이후 이벤트 수) — append 정합([[08-event-store-lifecycle]]).
- `DuplicateKeyException` → 동시성 충돌 매핑(시퀀스 채번 단일화).
- 🌱 핫스팟 슬롯 granularity와 교차-슬롯 불변식의 사가 위임 균형 — 이벤트 스토밍·[[05-aggregate-design]].

## 결과 (기대)
- 핫 스트림 경합이 큐로 직렬화되고 이중 점유가 구조적으로 불가능(L0).
- Redis 가용성과 무관하게 비관 의미론·정확성 유지.
- RFC-015(재개)가 본 ADR로 닫힘 — RFC→design_doc([[05-aggregate-design]])→ADR 체인 완결.
