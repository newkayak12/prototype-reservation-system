# ADR: 이벤트 정체성·전역 순서 — `event_id` + `global_seq` (adr/05 스키마 보강)

- **상태**: Proposed (2026-06-17) · 사이클 `20260612-v2-cqrs-es-architecture`
- **상위**: [[RFC-021-event-identity-and-global-ordering]] · **설계**: [[02-write-model]] · [[08-event-store-lifecycle]]
- **보강 대상**: [[05.event-store-mysql-table]] (합의됨·immutable) — 본 ADR이 그 `event_store` 스키마 블록을 보강한다(제자리 수정 대신 superseding ADR).
- **연관**: [[09.event-ordering-and-delivery-guarantee]] (inbox/멱등 키) · [[RFC-011-projection-rebuild-catchup]] (재구축 스캔)

## 맥락

[[05.event-store-mysql-table]]가 `event_store` 스키마를 `(aggregate_type, aggregate_id, sequence_no, event_type, event_version, payload, occurred_at)`로 박았다. 전수 감사([[04-design-completeness-audit]] ①)가 두 부재를 짚었다.

1. **정체성 부재** — `event_id`가 없어, 비-ES·lookup(상태+Outbox) 이벤트의 멱등/inbox dedup 키와 `causationId` 앵커가 정의 불가.
2. **전역 열거 커서 부재** — `sequence_no`가 per-aggregate라 재구축이 스토어 전체를 재개 가능하게 훑을 기준이 없음.

근거·옵션·기각은 [[RFC-021-event-identity-and-global-ordering]]. adr/05는 합의됨이라 immutable → 본 ADR이 **스키마만 보강**한다.

## 결정사항

**`event_store`에 `event_id`(전역 유일 정체성)와 `global_seq`(전역 삽입 커서) 두 컬럼을 추가한다. `(aggregate_id, sequence_no)` UNIQUE는 유지한다.**

```
event_store(
  global_seq   BIGINT AUTO_INCREMENT,   -- 재구축/백필 *열거*·재개 커서 전용. 교차-애그리거트 전순서 아님
  event_id     BINARY(16),              -- 전역 유일. inbox/dedup 키·causation 앵커·Kafka messageId
  aggregate_type, aggregate_id, sequence_no,
  event_type, event_version, payload(JSON), occurred_at,
  -- 봉투: correlation_id, causation_id, traceparent
  PRIMARY KEY (global_seq),
  UNIQUE (aggregate_id, sequence_no),
  UNIQUE (event_id)
)
```

- **`event_id`** — append/Outbox 기록 시점(트랜잭션 내) 채번. ES·비-ES·lookup 공통. **inbox dedup 키를 `event_id`로 일반화**([[09.event-ordering-and-delivery-guarantee]]의 `(aggregate_id, sequence_no)` inbox 키는 ES 특수 케이스로 흡수). ES Zero-Payload는 `sequence_no` 버전 가드를 병행.
- **`causationId` = 직접 원인 메시지의 `event_id`**(또는 `commandId`), **`correlationId` = 사슬 루트** 무변경 전파.
- **Kafka 파티션 키는 `aggregate_id` 불변**([[09.event-ordering-and-delivery-guarantee]]) — `event_id`는 정체성이지 라우팅 키가 아니다.
- **`global_seq`는 열거 커서 전용** — 용도는 `ORDER BY global_seq` 페이지네이션·재개. **교차-애그리거트 전순서 정확성은 보장하지 않는다.** 안전 근거: 재구축 백필은 커밋 완료 과거에 대한 배치라 AUTO_INCREMENT commit-skew/gap 무관, 실시간은 Kafka 구독([[RFC-011-projection-rebuild-catchup]]).

### 정확성 불변식

프로젝터 정확성 = **per-aggregate 순서(파티션 키) + 멱등 upsert + per-aggregate 버전 가드(`sequence_no`)**. 교차-애그리거트 적용 순서는 정확성 의존이 아니다(멱등이 흡수). 진짜 교차 순서·교차 불변식이 필요하면 **사가**([[08.saga-orchestration-vs-choreography]]·[[16.optimistic-concurrency-control]]). `global_seq`는 *진행/열거*를 나르지 *순서 정확성*을 나르지 않는다.

> 결정의 한 줄: "`event_id`가 정체성을 통일하고, `global_seq`는 순서가 아니라 재구축 *열거* 커서다 — 교차 순서는 여전히 사가."

## 장점

1. 비-ES·lookup 이벤트까지 단일 dedup 키(`event_id`) — 멱등이 컨텍스트 종류에 안 묶인다.
2. `causationId`/추적 메타가 실제 가리킬 앵커 확보 → [[10-observability]] 인과 사슬 성립.
3. 재구축이 결정적·재개 가능 열거를 얻으면서도, 비싼 전역 순서·전역 락을 사지 않는다(YAGNI 정합).

## 트레이드오프

### 선택한 방식의 한계
- 컬럼 2개·인덱스(UNIQUE `event_id`) 추가 — 쓰기 비용 소폭↑.
- `global_seq`가 "전역 순서처럼" 오용될 여지 — 문서·코드 주석으로 "열거 전용, 교차 순서 아님"을 명시해야 한다.

### 포기한 대안들
- **`occurred_at`+tiebreak 승격**: 시계 의존·교차 tiebreak 무의미 — 기각.
- **UUIDv7 PK 정체성·커서 겸용**: 책임 결합·근사 단조 — 기각(전용 `global_seq`가 명확).

## 미결정 사항 (→ 구현 사이클)
- `event_id` 표현(`BINARY(16)` vs `CHAR(36)`, UUIDv7 여부), Outbox 전파 배선.
- 비-ES inbox 생략 판정([[09.event-ordering-and-delivery-guarantee]] 연동).
- `global_seq` 페이지네이션·재개 체크포인트([[RFC-011-projection-rebuild-catchup]]).
